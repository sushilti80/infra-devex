### Remaining Owner / Action Before Release Sign-Off
- **Gap**: `tests/e2e/secretsBundles.spec.ts` (E2E-BUNDLE-001, E2E-BUNDLE-002) has never actually executed against real authentication — both scenarios skip via their own `HAS_E2E_AUTH` guard. Playwright browsers and the built/served frontend are confirmed working in-sandbox; the sole blocker is missing `E2E_TEST_USERNAME`/`E2E_TEST_PASSWORD` (an Entra ID test-tenant credential). `middleware/auth.js` has no dev-mode bypass, so this cannot be worked around by QA or Dev.
- **Owner**: SRE DevOps / Orchestrator (infrastructure/credential provisioning), per both the QA and SRE DevOps artifacts' own recommendation.
- **Action**: Provision `E2E_TEST_USERNAME`/`E2E_TEST_PASSWORD` (or an equivalent Entra ID test-tenant service account) as CI/sandbox secrets, then re-run `tests/e2e/secretsBundles.spec.ts` for real before this feature is signed off for production release. This is required before production promotion, not before sandbox deployment.
- Secondary, also non-blocking for sandbox: authenticate Wiz CLI (`WIZ_CLIENT_ID`/`WIZ_CLIENT_SECRET`) and run a real `wizcli` scan before production; install an axe-core-equivalent package to satisfy NFR-USA-001's automated accessibility assertion; split `resolution_latency_ms`/`commit_latency_ms` metric fields and load-test NFR-PERF-001 before relying on the p95 SLO in production.

### Rollback / Mitigation
- This feature adds a new, additive `bundleId`/`environmentSecrets[]` request shape (3-way `oneOf()` dispatch in `routes/api.js`) alongside the pre-existing singular/array-environment request shapes, which are confirmed unmodified and regression-tested (0 regressions across the full backend/frontend suites). The legacy "All Environments" submission flow remains the default-safe fallback and is unaffected if bundle-mode needs to be disabled.
- No schema migration or destructive data change is introduced: `data/secretBundles.json` is a new, additive config file; no existing vault, secret, or GitOps write path is altered.
- If a production issue is traced to bundle-mode submission after deployment, mitigation is to disable/hide the "Bundles" tab in `SecretsPage.vue` (falls back to the pre-existing "All Environments" flow, which has its own independent, unmodified test coverage) while the backend `oneOf()` dispatch can remain deployed inert (no client ever sends `bundleId` without the UI entry point). No server-side feature flag currently gates this path — recommend SRE DevOps add one if a fast kill-switch is desired before production promotion.
- Standing repo-wide dependency findings (js-yaml high, morgan/qs moderate) are tracked under the existing Vulnerability SLA and are not a rollback trigger for this feature specifically, since they are pre-existing and unrelated to this change.
