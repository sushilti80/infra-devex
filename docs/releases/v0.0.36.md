## Changes Shipped

### 🐛 Bug Fixes
- **Prefill instance count not restored** — Multi-instance modules (e.g., `appServiceWindows-1, appServiceWindows-2`) now correctly restore their saved instance count and names on edit instead of always showing 1 instance. Fixed by:
  - Adding `prefillInstances` prop to `ResourceForm.vue`
  - Creating `parseModuleInstances()` in CustomInfrastructurePage to map flat instance names → module types
  - Using longest-prefix matching to handle modules like `appServiceWindows`, `appServiceLinux`

- **RBAC relationships lost on submit** — Removed RBAC pairs were mysteriously re-appearing in deployment submissions. Root cause: v-model binding `v-model="rbacRelationships"` in RbacManager template didn't reliably propagate `.value` updates on every remove/add. Fixed by:
  - Replacing `v-model` with explicit `:modelValue` + `@update:modelValue="(val) => (rbacRelationships = val)"`
  - Ensuring both `removeRelationship()` and `addRelationship()` emit fresh array copies

### ✨ Features
- **Resource instance prefill prop** — ResourceForm now accepts optional `prefillInstances: Record<string, Array<{ name: string }>>` prop. When set, initializes module instances from prefilled data instead of single default instance.
- Added watcher on `prefillInstances` prop to re-initialize when it arrives after `selectedModules` (deferred load scenario).

### 🔒 Security
- Added **Key Vault Crypto User** role to `data/roles.json` for fine-grained encryption key access control (scope: `security`).

### 📋 Internal
- Updated `.github/copilot-instructions.md` **"Recent Feature Updates To Preserve"** section with complete prefill/edit wiring patterns:
  - Entry point and auto-load flow
  - `parseModuleInstances()` algorithm
  - ResourceForm prefill prop usage
  - RBAC v-model fix details
  - Reset paths on `clearEditingMode()` and `handleDeployAnother()`
  - Edge cases to preserve
